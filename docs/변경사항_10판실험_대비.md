# 20사이클 10판 실험(arm-20c) 대비 수정판 변경 사항

작성 2026-11-07 · 대상 코드 `unified-packages-fixed/` · 상세 근거 `CHANGES_EXPERIMENT30.md`

## 0. 요약

10판 실험(`runs/arm-20c`, 2026-11-06)은 승리 0판, 고발 6건 전원 오답으로 끝났습니다. 원인을 조사하는 과정에서 코드·프롬프트 문제 18건과 규칙 차원의 정보 부족이 드러났습니다.

수정판에서 바뀐 것은 세 갈래입니다.

1. **게임 규칙 변경 (팀 결정, 2026-11-07):** 방 단서 선착순, 동시 탐색의 우선순위, 이동 후 배치 공개, 거래 활성화, 미션 배부 전 달성 가능성 판정
2. **코드 결함 수정:** 말과 행동의 불일치, 답변 형식 오류, 질문 기한, 로그 누락, 미션 판정 2건, 이동 정보 누출
3. **프롬프트 전면 재작성:** 엔진 코드와 한 줄씩 대조해 틀린 설명 9건을 고치고, 빠진 규칙 6건을 넣음

규칙이 바뀌었으므로 **수정판 결과는 10판 실험과 직접 비교할 수 없습니다.** 10판 실험은 "수정 전 기준선"으로만 씁니다.

## 1. 10판 실험에서 확인된 문제 (변경의 근거)

## 2. 게임 규칙 변경

| 항목 | 10판 실험 | 수정판 | 위치 |
|---|---|---|---|
| 방 단서 | 누가 가져가도 남음. 모두 각자 사본을 얻음(기획서 v1.3) | **선착순, 복사 불가.** 가져가면 그 방에서 사라지고, 다른 사람은 질문·교섭으로만 얻음 | 엔진 규칙 `room_clues=first_come`(A9). `shared`로 되돌릴 수 있음 |
| 잔여 단서 정보 | 없음. 성공했는데 아무것도 못 얻어야 "소진"을 앎 | 탐색하면 주사위 결과와 무관하게 "그 방에서 내가 더 얻을 수 있는 수"를 받음. 추가 행동 없음 | A9 |
| 동시 탐색 | 요청이 엔진에 먼저 도착한 순. 병렬 실행에서는 LLM 응답 속도 경쟁 | 탐문·탐색 단계 끝에 한꺼번에 배분. 성공 확률 1 − ((기준선−1)/6)^주사위 수가 높은 사람부터, 같으면 무작위 | A14 |
| 위치 공개 | 이동을 내는 즉시 위치가 바뀌어, 늦게 움직이는 사람이 먼저 움직인 사람의 새 위치를 봄 | 이동 단계 동안에는 직전 배치가 보이고, 단계가 끝나면 전원 배치를 공개·기록 | A13 |
| 거래(교섭) | 실행 경로에 없음 | 기획서 A8 프로토콜대로 사용. 제안과 수락(역제안) 모두 그 단계의 행동 1회. 이행 결정을 미리 비공개로 냄(now / after_partner / withhold) → 일괄 정산. 둘 다 after_partner면 불발, withhold는 불이행 | B17, A17, B22 |
| 탐문·탐색 진행 | 각자 행동이 즉시 실행 | 모두 동시에 행동 또는 제안 → 행동 보류 → 교섭 정리(수락하면 낸 행동 포기) → 보류된 행동 실행 | A17 |
| 시간 초과 | 질문은 시한이 지나면 엔진이 기본 응답으로 대신 답함. 거래는 초 단위 시한으로 단계를 넘어 이어짐 | 단계는 모든 응답·교섭이 끝나야 넘어감. 오류 수준 시한(600초)을 넘긴 기계적 실패만: 교섭 취소(아무것도 오가지 않음) + 행동을 쓴 사람 모두 대체 행동 1회, 질문 실패 + 질문자 대체 탐색 1회 | A17 |
| 평판 | 저장만 되고 에이전트는 못 봄 | 같은 칸 플레이어의 풀 에이전트, 공개 평판, 나와의 거래 기록이 보임. 다음 게임까지 이어짐 | A16, B20 |
| 미션 배부 | 사이클 수만 일부 확인 | 배부 전에 이번 게임 설정에서 달성 가능한지 판정. 최소 사이클(미션별 표), 필요한 인원(다른 캐릭터·플레이어·NPC 수)을 확인 | A10 |
| 모호 진술 | "내 단서는 후보 X에 관한 것이 아니다"(정답 정보 없음) | 조합 배제 "X이면서 W인 조합은 정답이 아니다"(X는 응답자 확실 단서가 지운 후보, W는 질문자 가설의 다른 범주 후보). 한쪽이 확정되면 다른 쪽이 지워짐 | A18, B23 |
| 질문 방식 이름 | negotiate(교섭과 이름이 겹침) | persuade(설득). 효과는 같음 | – |
| 응답 시한 | 질문 30초, 거래 30초 | 병렬 실행 시 600초(오류 감지용) | I8, A17 |

규칙 변경에 대한 예상: 초반에는 탐색이, 단서가 바닥난 후반에는 질문과 교섭이 늘어납니다. 오프라인 시험(규칙 기반 가짜 LLM)에서는 칸 단서 50개가 9~10사이클에 바닥났습니다.

### 4.2 프롬프트: 틀렸던 설명

| 이전 프롬프트 | 실제 엔진 동작 | 출처 |
|---|---|---|
| 질문은 가설의 세 후보에 대해서만 답을 끌어낸다 | 확실·간접 단서는 가설과 무관하게 응답자가 고름. 가설은 모호 진술에만 쓰임 | 원본 |
| 가설의 place에 장소를 넣으면 간접 단서가 살아난다 | 위와 같은 이유로 틀림 | 수정본(FIX-B8) |
| negotiate는 교섭 제안을 겸한다 | 판정·효과가 question과 같음. 거래는 별도 | 원본 |
| 심문 실패 시 다음 사이클까지 질문할 수 없다 | 질문은 되지만 성공 0으로 처리 | 원본 |
| 협박 실패 시 내 단서 하나가 노출된다 | 단서 ID와 분류만 노출, 내용은 아님 | 원본 |

| 직전에 준비했으면 주사위 3개 | 다음 판정 행동까지 유지(이동이 끼어도) | 원본 |
| 답변 형태 1/2/3성공 고정 | 모호 자리에 간접 서술 포함, 선택지가 모자라면 가능한 만큼 | 원본 |
| 미션의 "교섭"과 negotiate 혼동 | 미션의 교섭은 거래 프로토콜 | 원본 |

### 4.3 프롬프트: 새로 넣은 규칙

- 모든 플레이어가 단서 0개로 시작하고, 단서가 없는 상대에게 질문하면 정보가 없다는 점
- 단서 50개의 구성과 방별 배치(6~7개), 선착순, 잔여 수 확인, 단계 끝 배분과 우선순위
- 모호 진술과 간접 서술의 실제 가치(정답 후보를 지우지 못함, 추론에 못 씀)
- 같은 추리 단계의 고발은 동시 판정, 출력 토큰 순 순위, 정답자가 나오면 즉시 종료
- 관계의 방향(보이는 값은 내가 상대에게, 미션은 상대가 나에게)과 시체 단서 소멸
- 거래 규칙 전체와 보유 공개가 미션에 주는 영향, 배치 공개

### 4.4 표시와 교훈 문구

- 남은 후보 목록의 순서를 섞습니다(0번 쏠림 대응).
- 질문 쪽으로 유도하던 교훈·전술 문구를 잔여 단서 기준으로 고쳤습니다.
- MBTI 경향 문구는 그대로 둡니다. MBTI는 16가지 독립 분류로서 B의 행동 원리이자 엔진 보정값이면 된다는 결정에 따른 것입니다.

## 6. 비교할 때 주의할 점

- 10판 실험은 수정 전 규칙과 코드로 돌았습니다. 승률이나 정보량을 직접 비교하면 규칙 효과와 코드 수정 효과가 섞입니다.
- 수정판 첫 캠페인은 반드시 새 에이전트 풀로 시작해야 합니다. 이전 풀의 교훈에는 바뀐 규칙과 맞지 않는 내용("탐색만 반복하지 말고 질문")이 들어 있습니다.
- `runs/v2-20c` 1판은 B13·B14·I8만 적용된 중간 상태의 기록입니다.

## 7. 추가 조사에서 확인된 문제

### 7.1 조사 중 발견해 고친 것

- **C8 (GM 참조 플레이어 회귀):** 칸 탐색 결과가 단계 끝에 나오도록 바꾼 뒤(A14), GM 쪽 스크립트 플레이어가 "빈 칸"을 알아채지 못해 탐색만 반복했습니다. 그 결과 GM 통합 테스트(`test_full_game_with_scripted_runtime…`)가 매번 실패했습니다. 나중에 확정되는 결과를 받아오게 고쳤습니다. 이 테스트는 원본에서도 확률적으로 실패하던 테스트라, 처음에는 기존 문제로 오인할 뻔했습니다.

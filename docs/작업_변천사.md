## 5. 규칙과 설계의 변화

### 5.1 정보 흐름 (11-07)
- 방 단서 **선착순, 복사 불가**, 탐색하면 남은 수를 알려줌(A9). 동시 탐색은 단계 끝에 성공 확률순 배분(A14).
- 이동 후 전원 배치 공개(A13). 개인 미션은 배부 전 달성 가능 판정(A10).
- 상호작용 단계 규칙 `simultaneous`: 모두 행동 또는 거래 제안을 동시에 내고, 제안이 정리되면 보류된 행동 실행(A17).
- 단서 흐름 boosted: 시작 시 확실 1 + 간접 2, 관찰 스킬 직업 +1, 후반 모호 응답 추가.

### 5.2 점수 (11-08, A24)
- 아무도 못 맞히면 생존자 전원 **−10**, 미션 무효. 누가 맞히기만 하면 다른 사람은 미션 점수 유지 → 누군가 푸는 쪽이 모두에게 이득.
- 부작용: 미션 점수가 10 이상이면 틀린 추리 도전(−20 + 미션 유지)도 손해가 아님 → v8에서 확신도 1% 미만 추리 도전 3건(13사이클 추리 도전 포함).

### 5.3 거래 (11-08, A25~A27, B29~B31)
- "X 유형을 주고 Y 유형을 원한다"로 선언. 유형 6개: 인물, 무기, 장소(확실) / 인물 위치, 흉기 위치, 동행(간접). 요청에 제외 번호를 붙일 수 있고 상대가 봄.
- 엔진은 보유만 확인. 실제로 넘길 단서는 각자 봉인(속일 수 있음). 수락 즉시 교환이 무조건 성립.
- 정직: 둘 다 +10, 기만자는 −20과 평판 하락. 취소는 시간 초과나 거절뿐.
- **엔진은 거래 이력을 기억하지 않는다.** 상대 기록은 에이전트가 자기 기억 파일에 남긴다(B30).
- 자유 담화 200자(질문, 답변, 거래). 거짓일 수 있고 믿음 계산에서 제외.

### 5.4 관계와 성격 (11-08, A28~A30, B32~B34)
- 에이전트 간 관계는 판이 지나도 유지(엔진 `agent_relationships`). 게임 속 관계(NPC 포함)는 매판 50. **11-09 A34로 대체**: 게임 밖 관계는 각 에이전트가 자기 기억에 직접 매긴다(9.8).
- 성격 보정 수치(A29)를 시도했다가 사용자 결정으로 **능력은 직업에만** 귀속 → 기본 꺼짐. MBTI는 선택 경향(가중치)으로만 작동하고 금지는 없다. v1.3의 MBTI 효과 3개는 유지.
- 모든 에이전트가 한 가지 최적 전략으로 수렴하는 것을 경계: 회고에서 성격을 버리지 않게 하고, 공통 처방을 삭제하고, 교훈은 사실로 기록.

### 5.5 판 끝 정보 (11-08, A31/B35)
- "누군가 맞혔다면 너는 Z점이었다", "가장 앞선 경쟁자는 R개까지 좁혔다". 게임은 경쟁 그대로, 공멸이 더 손해라는 사실만 공개.

### 5.6 GM과 엔진의 역할 분리 (11-08, A32/A33, B36, C14)
- GM이 진행자: 플레이어별 **행동 요구서**(합법 행동과 대상) 발행, 교섭 종료(RELEASE), 시간 초과 선언(EXPIRE), 단계 넘김.
- 엔진은 심판: 요구서 밖의 행동 거부. 주사위, 응답, 거래 결산은 에이전트가 엔진에 직접 요청한다(GM 병목 최소화).
- 효과(v7 1판 → v8 1판): 엉뚱한 상대 질문 34 → 0, 해석 불가 14 → 0, 대리 응답 14 → 0.

### 5.7 레벨 디자인 근거: 용량 시뮬레이션 (11-08)
- `sim_clue_capacity.py`(성격 없이 규칙만): 협력(욕심 많은 짝짓기) 시 20사이클에 94% 해결, 혼자서는 30사이클에도 0%. 방 단서는 6사이클 무렵 바닥남.
- 실제 에이전트는 "혼자" 쪽에 가깝다 → 교환 학습이 관건.

## 8. v8에서 확인한 문제 (18판 기준)

자세한 수치는 `docs/v8_캠페인_보고서_초안.md`에 있다.

- **거래는 늘었지만 불발도 많다.** 불발은 대부분 상대가 없는 유형을 요청해 정당하게 거절된 경우였다(282건 중 264건). 조건이 맞는 요청은 80%가 수락됐다. 그러나 거절된 요청을 같은 상대에게 다시 보낸 경우가 14%(45/312)였다. 에이전트가 "누가 무엇을 갖고 있지 않은지"를 기억하지 못한다.
- **고정 8개 목록이 중요도와 상관없이 정보를 밀어낸다.** 상대가 말한 보유 정보는 프롬프트에 중앙값 7사이클만 남았다.
- **기억 결함 (v8 전체에 영향)**
  - B38: 질문·탐색으로 얻은 단서를 0으로 기억했다. 질문 2,536회에 기억은 0개였고, 엔진 기준으로는 833개였다. 빈 칸 헛탐색은 실제의 약 2배였다.
  - B39: 거래한 단서가 복사된다는 사실이 거래 프롬프트에 없었다.
  - B40: 거래 거절과 상대의 말이 제안을 고르는 프롬프트에 없었다.
- **정답자 0.** 판 끝 남은 조합의 중앙값은 약 200개로 줄지 않았다.

### 9.1 결정 원칙

- **각 에이전트와 GM은 각자 고유한 기억을 가진다.** 기억은 공유하지 않는다(수렴 방지). 엔진은 여전히 에이전트의 거래 이력을 기억하지 않는다.
- **상대의 말은 '확실'이 아니라 '가능성'이다.** 상대의 말은 카드 보유를 추론하는 단서일 뿐 증거가 아니다.
- **GM 기억의 목적은 진행 안정화다.** 버그 같은 상황에서도 게임을 프로젝트 의도대로 계속 진행시키는 것이 목적이다. 이 처리는 판을 거듭하며 학습되어야 한다.
- **GM의 처치는 게임 결과를 바꾸지 않는다.** GM은 플레이어 대신 행동하지 않고, 시간이 결과를 정하지도 않는다.
- **용어**: 추리 단계의 지목 행동은 보고서에서 "추리 도전"이라고 부른다.

### 9.3 GM 기억 (C15)

- GM 자신의 파일 `agent-memory/gm_<GM>.json`에 기록한다.
- **감지하는 상황**: 단계 정체(플레이어 무응답, 요구서 미발행, 단계 넘김 실패, 답변 대기), 엔진 일시 오류, 명령 거부
- **처치**: 대기, 다시 동기화, 요구서 재발행, 간격을 둔 재시도. 운영자 호출은 다른 처치를 모두 써 본 뒤의 마지막 수단이고, 해결 점수를 주지 않는다.
- **학습**:
  - 상황 유형과 처치별로 해결률과 해결 시간을 쌓아 다음 판의 선택에 쓴다.
  - 정체 기준도 학습한다. 이 풀에서 단계별로 실제 걸린 시간의 상위 10% 값을 2배 한 값이며, 60~900초 범위로 제한한다.
- 상태: 구현·테스트 완료

### 9.8 에이전트 관계도와 T/F 관계 경로 (11-09 결정, 교재 I·II 검토 후)

v8 20판의 MBTI 분석은 성격별 전략 프롬프트가 행동을 얼마나 독립적으로 가르는지를 봤습니다.
- **갈린 것**: T/F는 설득, 심문 회피, 정직에서는 갈렸습니다.
- **갈리지 않은 것**: "관계로 판단한다"는 F의 핵심은 T와 같았습니다.
- **원인**: 엔진의 관계 값은 질문 성과와 거래 이행으로만 바뀌고, 담화는 반영되지 않습니다. 이익을 주고받는 '이성'의 경로만 있고 '감성'의 경로가 없었습니다.

**결정 원칙**
- 게임 밖의 에이전트 관계도는 **각 에이전트가 자기 기억에 고유하게** 둡니다(50에서 시작). 서운하거나 손해를 보면 내리고, 고맙거나 친밀해지면 올립니다. 엔진이 들고 있으면 스탯이 됩니다.
- 에이전트는 자기가 생각하는 관계를 **GM에게 보고**하고, **GM이 취합해 엔진 기록에 남깁니다**. 기록 전용이며 판정·운영에 쓰지 않습니다.
- **F**: 관계를 쌓다 보니 실리가 따라옵니다.
- **T**: 관계를 이익의 교환으로 쌓으며, 단기 실리와 사람 우선 교류 중 하나를 고르는 갈림길이 있습니다.
- 사용자 제안을 그대로 받지 않고, 교재 I·II를 기준으로 적절성을 검토해 먼저 보고한 뒤 반영했습니다.

- **B57 모든 성향·조합 문구를 원인 중심으로**: "그래서 …" 같은 대가 문장, "크게 흔들린다" 같은 결과로 쓴 반응, "탐색한다" 같은 처방 행동을 빼고, 각 유형이 무엇을 중요하게 여기고 어떻게 느끼는지로 다시 썼습니다. 정의(E/I 무리의 규모, S 확신, N 선취, T/F 관계 경로, J 약속, P 즉흥)는 그대로입니다. 회고 지시의 유형별 처방도 "네 성향이 중요하게 여기는 것에 비추어"로 바꿨습니다.
